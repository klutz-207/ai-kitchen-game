# 美术实现规范

## 目标

本项目的美术方向是 **像素风格 + 简笔画感** 的 AI 厨房游戏。美术素材需要同时满足两个目标：

1. 视觉上统一：菜品、客人、食材、特效都像来自同一个游戏世界。
2. 技术上可用：能够被 React 前端直接展示、叠放、动画化和复用。

本规范用于统一图片素材的格式、尺寸、背景、命名和前端使用方式。

---

## 总体原则

### 1. 前端最终使用的素材统一为透明 PNG

推荐格式：

```text
PNG
RGBA
透明背景
方形画布
```

原因：

- PNG 支持透明通道，适合放在盘子、桌面、卡片、气泡框等不同背景上。
- PNG 不会像 JPG 一样产生压缩脏边，适合像素风和清晰轮廓。
- React 前端可以直接通过 `<img>`、CSS、Canvas 或动画库使用。

### 2. 透明底是游戏素材的基础要求

最终进入游戏页面的素材应统一为：

```text
transparent background
no white box
clean edge
```

### 3. 方形画布是默认规范

建议所有可独立展示的游戏素材都使用方形画布：

```text
1024x1024  源图 / AI生成图
512x512    标准素材图
256x256    页面展示大图
128x128    常规 UI 图标 / 小菜品
64x64      小图标 / 状态图
```

方形不是美术上绝对必须，但它能让前端布局更稳定，尤其适合：

- 菜品图
- 食材图
- 客人头像
- 表情图
- 徽章图标
- 评分图标

## 素材类型

### 1. 菜品素材

用于展示玩家生成的料理，包括第一道菜、第二道菜和融合后的最终料理。

推荐规格：

```text
格式：PNG
背景：透明
画布：方形
源图尺寸：1024x1024
前端显示：128x128 / 256x256
风格：像素风、简笔画轮廓、中心构图
边缘：干净，无白边，无灰边
```

菜品图片应满足：

- 主体居中，四周留出适当透明边距。
- 轮廓清晰，缩小后仍能看懂是什么。
- 避免复杂背景、桌布、厨房场景等内容进入素材本身。
- 不要把文字直接画进菜品图里，菜品名称由前端文本展示。

示例命名：

```text
dish_first_love_pudding.png
dish_moonlight_soup.png
dish_fusion_memory_cake.png
```

### 2. 客人素材

用于展示到店客人、表情变化和反馈阶段状态。

推荐做成多张透明 PNG：

```text
guest_heartbroken_idle.png
guest_heartbroken_thinking.png
guest_heartbroken_happy.png
guest_heartbroken_moved.png
```

如果后续需要更强动画，也可以使用 spritesheet：

```text
guest_heartbroken_idle_spritesheet.png
```

客人素材建议保持：

- 同一角色的头身比例一致。
- 表情变化明显，但姿势变化不要过大。
- 背景透明，方便放在主界面右侧或对话气泡旁。

### 3. 食材与装饰素材

用于交互、拖拽、叠加或构建菜品。

这类素材应拆成独立透明 PNG，例如：

```text
ingredient_stardust.png
ingredient_berry.png
ingredient_memory_cube.png
decor_sparkle.png
decor_steam.png
decor_sauce_drop.png
```

拆分素材的好处：

- 前端可以独立移动、旋转、缩放。
- 可以做拖拽、点击、悬浮等交互。
- 可以在融合动画中单独飞散、发光或组合。

### 4. 特效素材

用于表现烹饪、融合、评分、稀有度等反馈。

推荐类型：

```text
effect_steam.png
effect_sparkle.png
effect_light_beam.png
effect_rare_star.png
effect_ssr_glow.png
```

特效可以用：

- 透明 PNG 单图
- 透明 PNG spritesheet
- CSS 动画生成
- Canvas 粒子效果

优先级建议：

1. 简单发光、漂浮、缩放：用 CSS。
2. 重复帧动画：用 spritesheet。
3. 大量粒子、融合爆发：用 Canvas。

## 动态素材规范

### 1. 多图层透明 PNG

如果一个菜品需要被动画化，不建议只生成一张完整图片。可以拆成图层：

```text
plate.png
food_base.png
topping.png
steam.png
sparkle.png
sauce.png
```

前端通过绝对定位叠放：

```tsx
<div className="relative w-64 h-64">
  <img src="/assets/dishes/plate.png" className="absolute inset-0" />
  <img src="/assets/dishes/food_base.png" className="absolute inset-0" />
  <img src="/assets/dishes/steam.png" className="absolute inset-0 animate-float" />
</div>
```

适合场景：

- 蒸汽上浮
- 星星闪烁
- 酱汁滴落
- 菜品轻微晃动
- 融合前后图层变化

### 2. Spritesheet

如果需要像素动画，可以使用 spritesheet，也就是一张 PNG 中包含多帧。

推荐规格：

```text
格式：PNG
背景：透明
帧尺寸：128x128 或 256x256
帧数：4 / 6 / 8 / 12
排列：横向排列优先
```

示例：

```text
dish_bubbling_spritesheet.png
8 frames
each frame 128x128
total size 1024x128
```

前端可通过 CSS `steps()` 播放：

```css
.dish-bubbling {
  width: 128px;
  height: 128px;
  background-image: url("/assets/effects/dish_bubbling_spritesheet.png");
  background-size: 1024px 128px;
  animation: bubble 800ms steps(8) infinite;
}

@keyframes bubble {
  from {
    background-position: 0 0;
  }
  to {
    background-position: -1024px 0;
  }
}
```

## AI 生图与后处理流程

### 推荐流程

```text
玩家输入创意概念
→ 后端整理生图 prompt
→ 图片模型生成 1024x1024 透明背景图片
→ 后处理：裁剪 / 清理边缘 / 像素化 / 压缩
→ 保存为透明 PNG 或 WebP
→ 前端通过 URL 展示
```

### 生图 Prompt 建议

可在图片生成智能体中加入类似约束：

```text
pixel art style, simple doodle outline, centered fantasy dish,
clean silhouette, no text, no logo, no background objects,
transparent background, isolated game asset, readable at small size
```

如果图片模型意外生成了底色或边缘脏色，需要在后处理阶段移除，最终仍然交付透明 PNG。

### 后处理要求

生成结果进入前端前，建议完成：

- 裁剪主体并保持方形画布。
- 移除任何背景色，导出透明背景。
- 清理白边、灰边、半透明脏边。
- 统一缩放到标准尺寸。
- 必要时进行像素化和颜色数量控制。

## 前端接入方式

### 1. 静态素材

手工制作或预生成素材建议放在：

```text
public/assets/
```

建议目录：

```text
public/assets/dishes/
public/assets/guests/
public/assets/ingredients/
public/assets/effects/
public/assets/ui/
```

React 中直接引用：

```tsx
<img
  src="/assets/dishes/dish_moonlight_soup.png"
  alt="月光汤"
  className="w-32 h-32 object-contain pixelated"
/>
```

像素风图片建议加上：

```css
.pixelated {
  image-rendering: pixelated;
}
```

### 2. 动态生成素材

由后端生成的图片不建议直接塞进前端代码仓库。更合理的方式是：

```text
后端生成图片
→ 保存到对象存储或可访问静态目录
→ 数据库或缓存记录图片 URL
→ 前端拿 URL 渲染
```

前端使用方式：

```tsx
<img
  src={dish.imageUrl}
  alt={dish.name}
  className="w-64 h-64 object-contain pixelated"
/>
```

## 推荐文件命名

统一使用小写英文、下划线分隔：

```text
类型_对象_状态.png
```

示例：

```text
dish_moonlight_soup.png
dish_memory_cake_fusion.png
guest_artist_idle.png
guest_artist_happy.png
ingredient_stardust.png
effect_steam_loop.png
ui_button_cook.png
```

不建议：

```text
菜品1.png
new image final final.png
IMG_20260503.png
```

原因是中文名和空格在跨平台路径、部署、缓存和脚本处理中更容易出问题。

## 当前阶段建议

现阶段还在产品设计和玩法验证阶段，建议先建立一套最小素材标准：

### 必备素材

```text
客人头像：3-5 个角色，每个角色 2-3 个表情
菜品图：10-20 张测试菜品
基础特效：蒸汽、星星、光束、评分星
UI 图标：开始、发送、融合、重做、下一位客人
```

### 交付格式

每个素材至少交付：

```text
透明 PNG：用于前端
源文件：用于后续修改
```

如果是 AI 生成素材，还应记录：

```text
生成 prompt
生成时间
后处理步骤
最终文件名
```

## 一句话结论

本项目最终进入游戏页面的核心图片素材，应统一为：

```text
方形画布
透明背景
PNG 格式
清晰轮廓
像素风 + 简笔画感
可被前端直接缩放、叠加和动画化
```

如果需要交互和动态效果，则进一步拆成：

```text
多层透明 PNG
或透明 PNG spritesheet
```
