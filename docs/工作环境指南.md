# 工作环境指南

## 目标

这个工作区要同时服务两件事：让你快速判断项目下一步该做什么，也让我在接手时能稳定找到上下文、运行检查、保护已有成果。

## 每次开工先看

1. `README.md`：项目入口、命令和目录地图。
2. `docs/协作看板.md`：当前优先级、待办和验收口径。
3. `docs/产品需求文档.md` 与 `docs/game-flow.md`：玩法主线。
4. `docs/后端接口与Mock策略.md`：接口和 mock 边界。
5. `assets/art-library/README.md` 与 `assets/art-library/manifest.json`：可用美术素材。

## 本地运行

```powershell
npm run check
npm test
npm run build:demo
npm run dev
```

默认服务：

- 前端 Demo：http://127.0.0.1:5174
- Mock API：http://127.0.0.1:3001

如果只改 API，运行 `npm run dev:api` 和 `npm test`。如果只改界面，运行 `npm run dev:demo` 和 `npm run build:demo`。

## 给 Codex 的工作约定

- 先读相关文档和已有代码，再改文件。
- 不覆盖人工写过的设计文档，新增结论优先写到 `docs/协作看板.md` 或新文档。
- 涉及玩法、客人库、评分逻辑时，同步补测试或写明未覆盖原因。
- 涉及真实 AI API 时，默认保留 mock fallback，避免演示现场被网络、额度或生图服务卡住。
- 所有真实密钥只放 `.env`，用 `.env.example` 说明变量名。

## 比赛前优先级

1. 形成一条稳定可演示闭环：选择客人、输入灵感、生成两道菜、融合、反馈。
2. 提升“AI 厨房”的独特感：情感需求、创意食材、像素菜品和评价语言要互相呼应。
3. 保证演示可靠：mock 数据可跑，智谱 GLM / CogView 接入失败时也能继续演示。
4. 保留过程材料：产品判断、玩法迭代、美术规范和接口策略都能在 `docs/` 里找到。
