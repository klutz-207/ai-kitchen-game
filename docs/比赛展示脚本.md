# 比赛展示脚本

更新时间：2026-05-14

## 3 分钟演示路径

### 0:00-0:25 开场

一句话介绍：

> AI 厨房是一款把抽象情绪做成像素料理的 AI 游戏。客人说的不是菜名，而是“我想吃一点能照亮孤独的东西”这样的情感需求，玩家用文字给出创意食材，AI 把它变成可视化料理和情感反馈。

展示点：

- 打开 demo 首屏。
- 选择一个主厨形象。
- 点击“开始营业”。

### 0:25-1:10 客人需求

讲述重点：

- 客人不是普通点餐，而是带着情绪状态进入厨房。
- 已内置 6 类客人：失恋青年、加班程序员、旅行少女、天文研究员、害羞小学生、记忆老人。
- 每个客人都有不同的情绪目标、引导话术和反馈风格。

推荐演示客人：

- 失恋青年：容易理解，情绪强。
- 天文研究员：画面感强，适合展示“抽象概念变食材”。
- 害羞小学生：可爱，反馈有温度。

### 1:10-1:55 两轮创作

操作：

1. 第一轮输入一个情绪食材，例如“初恋下午的阳光和透明糖霜”。
2. 等待生成第一道菜。
3. 第二轮输入补充概念，例如“旧信、晚风和一点刺痛的果冻”。
4. 等待生成第二道菜。

讲述重点：

- 这不是固定菜谱，而是开放式文字创作。
- 文本模型负责理解情绪、提取视觉概念、生成菜名和生图 prompt。
- Demo 默认保留 mock fallback，所以即使现场网络或模型失败，也能稳定演示完整流程。

### 1:55-2:30 融合与反馈

操作：

1. 点击“融合”。
2. 展示最终料理。
3. 点击“端给客人”。
4. 展示客人反馈与评分。

讲述重点：

- 两道菜不是简单并列，而是通过融合形成最终料理。
- 客人反馈包括情感回复、满意度、创意度、稀有度。
- 评价不是单纯数值，而是回到客人的情绪需求：这道菜有没有回应他真正想要的东西。

### 2:30-3:00 技术与收束

技术口径：

- 前端：React + Tailwind CSS + Vite。
- 后端：Vercel Serverless API routes。
- 文本模型：智谱 GLM-4.7-flash，使用 OpenAI-compatible API。
- 图像模型：智谱 CogView-3-Flash 云端生图，Stable Diffusion WebUI / PixelRTXL 作为可选本地图生图方案。
- 兜底：本地 mock pipeline，保证比赛展示可靠。

结尾话术：

> AI 厨房想展示的不是“AI 替玩家做菜”，而是“AI 接住玩家的想象力”。玩家负责提出有情绪的创意，模型负责把它翻译成可看、可评价、可继续讲故事的料理。

## 演示输入备选

### 失恋青年

- 第一轮：初恋下午的阳光和透明糖霜
- 第二轮：旧信、晚风和一点刺痛的果冻

### 加班程序员

- 第一轮：凌晨两点的咖啡、热汤和通过测试的提示音
- 第二轮：把 bug 炸成脆片，再撒一点薄荷清醒感

### 天文研究员

- 第一轮：流星落进热茶里，像一小口会发光的孤独
- 第二轮：月尘、观测站的毛毯和银河形状的奶冻

### 害羞小学生

- 第一轮：跳跳糖、热牛奶和一面小小的勇气旗
- 第二轮：把紧张揉成软云，再做成会鼓掌的星星

## 风险兜底话术

- 如果真实图像生成慢：当前展示的是稳定 mock 版本，真实模型链路已按相同 API shape 接入，后续替换服务不影响前端。
- 如果评委问为什么是两轮：比赛 demo 用两轮压缩演示时长，早期 3-4 轮深聊方案保留为扩展模式。
- 如果评委问创新点：重点在“情绪需求驱动的开放式创作”和“文本理解、图像生成、角色反馈组成的游戏闭环”。
