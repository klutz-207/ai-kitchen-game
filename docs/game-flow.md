# 游戏主流程

## User Goal
玩家用两轮高密度创意输入生成两个菜品，并融合为最终料理，满足客人的情感需求。

> 说明：早期方案是 3-4 轮深聊。当前比赛 demo 采用 2 轮创作，是为了控制演示时长并稳定跑完“生成两道菜 → 融合 → 反馈”的完整闭环。后续可在真实模型稳定后恢复为 3-4 轮扩展模式。

## Entry Points
- 玩家点击"开始营业"，第一位客人到来
- 上一局结算后，"下一位客人"按钮 → 下一位客人到来

## Preconditions
- 客人数据已加载（`guests.json`）
- 对话模型 API 可用
- 生图模型 API 可用

---

## Happy Path

### 阶段一：客人到来

1. 主界面——客人站在右侧，展示描述词（如"穿旧外套的失恋青年"）
2. 客人以对话气泡说出开头话（如"我想吃点带有她的味道的"）
3. 画面左侧1/4~1/3处，厨师（玩家）背影出现，背对屏幕

### 阶段二：进入创作

4. 厨师背影右上角冒出气泡框，框内3个圆点依次闪烁（加载中）
5. 气泡框逐渐放大至覆盖全屏，过渡到白屏创作页
6. 白屏上方：对话模型流式输出第一句引导词
7. 白屏下方：玩家输入框 + 发送按钮

### 阶段三：两轮创作

8. 玩家输入第1轮回答 → 发送
9. 对话模型锁定关键词，流式输出第2轮引导提问
10. 玩家输入第2轮回答 → 发送
11. 对话模型判断信息量充足 → 流式输出"正在为你烹饪..."提示 → 自动触发生图

> 当前 demo 每道菜对应一轮核心输入。若扩展为深聊模式，可在每道菜生成前加入 2-3 个追问。

### 阶段四：生成菜品一

12. 白屏上方切换为生成状态：「正在烹调第一道菜...」+ 加载动画
13. 生图模型返回第一张菜品图片 + 菜品名称
14. 白屏像纸张卷起/缩小退回气泡框，过渡回主界面
15. 主界面中央展示菜品一（像素风格，带入场动画）

### 阶段五：生成菜品二

16. 主界面菜品二位置显示虚线卡片 + 脉冲动画 + "还差一道..."提示
17. 玩家进入第二轮创作并输入新的情绪食材
18. 生图模型返回第二张菜品图片 + 菜品名称
19. 菜品二展示在菜品一右侧，两张菜品并排陈列
20. 页面最下方滑入"融合"按钮（带弹跳动效）

### 阶段六：融合

21. 玩家点击"融合"
22. 背景短暂变暗，两张菜品卡片向中心靠拢，绕中心旋转加速
23. 一道光束从中心爆发
24. 融合完成——最终料理图片 + 名称居中展示（比两张子菜品更大）
25. 光束消散的余烬粒子飘向客人方向，过渡到反馈阶段

### 阶段七：客人反馈

26. 客人头像旁弹出思考气泡
27. 对话模型按客人预设提示词生成评价 → 流式显示文字反馈
28. 客人表情变化（从期待 → 惊喜/满意/感动），数值评分依次弹出（满意度、创意度、稀有度）

### 阶段八：结算

29. 评分卡片从下方向上滑入，展示三项评分数值
30. "下一位客人"按钮出现，点击回到阶段一

## 界面跳转总览

```
主界面(客人+厨师背影)
  → 气泡放大 → 白屏(创作)
    → [2轮创作]
    → 加载态(生图一)
  → 白屏收缩退回气泡框 → 主界面(菜品一)
    → 虚线卡片脉冲(等菜品二)
  → 主界面(菜品一+菜品二+融合按钮)
    → 背景变暗 → 菜品旋转+光束 → 融合完成
  → 主界面(最终菜品)
    → 客人反馈(流式文字+表情变化+评分弹出)
    → 结算卡片上滑
  → "下一位客人" → 主界面(下一客人)
```

## Decision Points

| 决策点 | 触发条件 | 处理 |
|--------|----------|------|
| 生图时机 | 对话模型判定信息充足 且 ≥3轮 | 对话模型输出过渡语后自动触发 |
| 第4轮强制生图 | 已满4轮但信息仍不足 | 对话模型输出总结性过渡语，强制触发生图 |
| 重做单个菜品 | 玩家点击菜品旁的"重做"按钮 | 仅该菜品重新生成，另一张保留 |
| 重做全部 | 玩家点击"全部重做" | 清空两张菜品，回到阶段四重新开始 |
| 生图失败 | API返回异常 | 自动重试1次；仍失败则用占位剪影 + "菜糊了..."文案 |

---

## Edge & Recovery States

| 状态 | 表现 | 处理 |
|------|------|------|
| 玩家输入为空 | 发送按钮置灰，输入框下方轻提示"写下你的灵感..." | 阻止提交 |
| 玩家输入跑题 | 对话模型在下一轮引导中温和拉回 | 不打断，靠模型纠偏 |
| 生图API超时 | 白屏加载动画持续 + "火候有点大，稍等一下..." | 30秒超时，自动重试 |
| 生图安全过滤 | 提示"这个食材太奇怪了，换一种试试？" | 回到上一轮对话 |
| 融合前退出 | 弹出确认"菜品还没融合，确定离开吗？" | 确认后返回，菜品保留 |
| 网络断开 | 页面顶部横条提示"网络断开，正在重连..." | 重连后恢复当前步骤 |

---

## Risks and Open Questions

- 对话模型能否可靠判断"3轮还是4轮"？需要 prompt 里明确判断规则
- 像素风格一致性由生图 prompt 控制，需要提前单独调优
- 生图模型延迟影响节奏——生图一和生图二的等待总时长需控制在合理范围
- 融合动画实现方案未定（CSS / Canvas / Lottie？）
- 两轮生图是否可以用同一个生图模型调用并行处理来加速？
