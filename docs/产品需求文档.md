# AI厨房游戏 - 产品需求文档

## 产品概述
- **产品名称**：AI 厨房
- **核心玩法**：通过文字交互，创造回应情感需求的创意菜品
- **创新点**：用大模型把抽象情绪转译成可视化料理，并用客人反馈形成情感闭环
- **目标用户**：年轻人为主，受众面广
- **截止日期**：2026年5月14日
- **当前形态**：React 可演示 demo + Vercel API routes + mock/真实 AI 双链路

---

## 游戏流程

### 主流程
```
客人到来 → 展示需求 → 玩家输入 → 大模型引导 → 生成菜品 → 客人反馈
```

### 详细流程
1. **客人到来**：展示客人像素形象和背景
2. **展示需求**：客人提出抽象需求（如"想要甜的东西"）
3. **引导话术**：系统给出引导（如"什么是甜的呢？回忆、爱情也是甜的"）
4. **玩家输入**：玩家输入文字描述（如"初恋的味道"）
5. **大模型引导**：大模型询问更多细节（如"希望它呈现什么形式？"）
6. **生成菜品**：
   - 提取名词作为核心食材
   - 生成像素风格静态图片；无真实模型时使用稳定 mock 料理
   - 前端添加动态效果（旋转、闪烁、浮动）
   - 生成菜品名称
7. **客人反馈**：
   - 情感回复（智能体生成）
   - 数值评价（满意度、创意度、稀有度SR/SSR）
   - 表情变化

---

## 游戏内部智能体（运行时功能）

### 1. 引导智能体
- **职责**：引导用户创作
- **输入**：用户文字、客人需求
- **输出**：引导问题、提取的名词
- **约束**：不能太局限，要鼓励创造力

### 2. 图片生成智能体
- **职责**：生成菜品图片和名称
- **输入**：名词、上下文、形式要求
- **输出**：像素风格图片、菜品名称
- **约束**：白底、无底、像素风格、可直接用于页面

### 3. 客户反馈智能体
- **职责**：生成客人反馈
- **输入**：菜品名称、客人需求
- **输出**：情感回复、数值评价
- **约束**：符合客人性格，评价合理

## 客人系统

### 客人类型（v1 已内置 6 个）
- 失恋青年：回忆、酸甜、旧信、晚风
- 加班程序员：重启、清醒、夜宵、bug
- 旅行少女：归途、方向感、家乡、地图
- 天文研究员：孤独、星光、观测站、宇宙
- 害羞小学生：勇气、上台、紧张、掌声
- 记忆老人：老照片、米香、时间、旧名字

### 客人属性
- 形象：像素风格头像
- 背景：简短介绍
- 需求：抽象的情感需求
- 引导话术：引导玩家创作的提示
- 反馈模板：不同满意度下的回复模板

## 技术架构

### 前端
- React + Tailwind CSS
- CSS动画实现动态效果

### 后端
- Vercel Serverless API routes
- Node.js 运行时
- 内存 session store，用于本地 demo 和短时演示

### 大模型链路
- 默认演示：Mock 服务，保证无 key、无生图服务时也能完整跑通
- 真实文本理解：Qwen Flash（OpenAI-compatible API）
- 真实图像生成：Stable Diffusion WebUI + PixelRTXL

### 部署
- Vercel 承载前端与轻量 API
- 真实生图服务建议本地或独立 GPU 服务承载
